## 2. TOOL INVENTORY (from `ls scripts/`, docstrings read where relevant)

Geometry / reference-relevant tools, one line each:

- `skyline_panel.py` — builds a geometry GUIDE (rsvg-based) to feed image-gen and CHECKs a candidate against real SVG geometry via overlay; proven on Marriott/Cap Juluca panel specs (`aspect=0.6893/0.3895` in `tasks/marriott-hospital/BRIEF.md`).
- `master_spec.py` — geometry contract v2 extractor from a master-template Illustrator artboard render + JSX census; emits per-panel mask/control/forbidden/holes + spec.json; fixed the dash-leak and synthetic-anchor-inflation bugs (commits 4d93530, a8b775f — see evidence table).
- `svg_to_controlmap.py` — renders a clean ControlNet conditioning map from the AUTHORITATIVE SVG geometry (not a model-guessed line-art map) — exact contour source for ControlNet routes.
- `outset_cutouts.py` — writes a variant SVG whose internal cutouts are buffered outward by N user-units, leaving the outer contour unchanged; proven fix for cutout-drift (space-np01, default outset=30).
- `controlnet_sdxl_gen.py` — GEOMETRY-EXACT generation via SDXL-inpaint + xinsir canny SDXL ControlNet, fed the authoritative SVG geometry + a hole mask that is never generated (kept white by construction).
- `measure_sdxl_cn.py` — measures a `controlnet_sdxl_gen.py` output's geometry against the exact SVG masks it was generated from + draws an overlay.
- `controlnet_gen.py`, `controlnet_inpaint_gen.py`, `controlnet_style_gen.py`, `controlnet_sweep.py` — SD1.5-family ControlNet variants (lineart/inpaint/style/sweep); `controlnet_style_gen.py` (as `controlnet-style-sd15`) is the highest region-IoU non-hybrid method measured in space-np01-front-bottom-02 (0.969).
- `register_to_svg.py` — registers a free-form subscription-gen panel illustration (roughly right shape, not pixel-exact) onto the EXACT die-cut SVG geometry, clips outside-contour paint to white and punches cutouts.
- `exact_bevel_composite.py` — GUARANTEED-EXACT re-seat compositor: places openings at exact SVG coords with an illustrated bevel rim while preserving the model's painting elsewhere; proven last-resort backstop, degrades style (see evidence table RESEAT rows) — never the default.
- `geom_gate.py` — deterministic geometry HARD-GATE (fill/overflow/edge-IoU vs a mask), runs BEFORE any VLM judge; used across Marriott t2/t3 bundles (fill_inside_contour, edge_iou fields).
- `geom_iou.py` — fill-agnostic region-IoU metric ("does the opening appear at the right location/shape regardless of fill") — the primary space-np01-front-bottom-02 gate metric.
- `svg_geometry_check.py` — white-IoU metric (are the openings actually white/empty) — the companion metric to `geom_iou.py`; the two can disagree on offset/short paint (see RESEAT-it4-nb-s2 row).
- `svg_geometry_report.py` — parses an SVG template into a geometry report identifying outer contours, holes, slots, dashed safe-area contours, and keep-clear zones; first step in the standard SVG-template workflow.
- `svg_manifest.py`, `svg_classify.py`, `vector_spec.py` — SVG manifest/classification/vector-spec extraction utilities feeding the gates.
- `gates.py` — runs all deterministic panel gates and emits one bundle from `vector_spec.py` geometry products.
- `forbidden_gate.py` — advisory salient-feature check inside forbidden zones (e.g. red-dashed stripes over center stabilizer slots on the master template).
- `judge.py` — programmatic VLM verdict (OpenAI gpt-4o vision) for image edits/checks — strict-JSON automated eyeball.
- `judge_panel.py` — builds a JUDGE PACKET for a whole-panel illustration (registered overlay + per-cutout hi-DPI crops + deterministic geometry floor) for the A-G VLM rubric.
- `judge_tiles.py` — tiles a candidate for reliable VLM judging (fixes downsampling hallucination on tall/large panels — "a window present mid-height was scored absent" without tiling).
- `dup_detect.py` — code-based duplicate-element detector (catches e.g. a stacked double window/door a VLM count-gate missed) backing the VLM count gate.
- `style_packet.py` — auto-extracts style-reference crops from a finished illustration; docstring states the governing LAW: "reference beats prose."
- `build_reference_style_packet.py` — builds the full visual style packet (contact sheet + exemplar sheet + JSON) from task reference images for style/image-gen agents; proven on Marriott (`tasks/marriott-hospital/style-packet/`).
- `verdict_form.py` — generates a structured review-verdict form for a gen round (one short form per round rather than free prose, per PROCESS-V3 law 8).
- `subgen.py` — the single always-working subscription image-gen wrapper (codex + agy), used across both marriott-hospital and space-np01 as the default generation entry point.
- `falgen.py` — fal.ai image-edit engine (Flux Fill masked inpaint / Flux Kontext instruction edit / Flux.2 edit); used for the r13 door-leaf cross fix (masked-inpaint) per commit c07dff4.
- `onepass_gen.py` (referenced in wiki, not in current `scripts/` ls — confirm before reuse; wrapper for the fal-ai/flux-control-lora-canny + LoRA one-pass route per `wiki/concepts/onepass-geometry-style-route-flux-control-lora.md`).
- `outer_loop.py`, `run_matrix.py`, `sweep.py` — batch/matrix orchestration for multi-candidate generation sweeps.
- `objective_gate_report.py`, `results_db.py`, `build_dashboard.py` — aggregate gate results into reports/DB/dashboard; `results_db.py` auto-generates `RESULTS-BOARD.md` from all experiment dirs (space-np01 RESULTS board footer: "Auto-generated by `scripts/results_db.py`").

## 3. TOP-10 LESSONS RANKED BY HOW BINDING THEY SHOULD BE ON THE v2 WORKFLOW DESIGN

1. **Reference IMAGES beat prose, measured, not just asserted.** A/B test on Marriott r6: ref+text region/geom-IoU 0.9989 vs text-only 0.8352 (commit 3b0beb2). This is the single hardest number in the repo backing LAW 0 — the v2 workflow must make image-attachment the default path with no prose-only fallback silently accepted.
2. **Geometry-exact and style-gorgeous have NOT been solved simultaneously by any single measured method in this repo.** ControlNet SD1.5 hits region-IoU 0.92–0.969 but "flat navy wash, NO painted rims" (DREAM1); re-seat hits 0.935 IoU but "dark monochrome, not the bright colorful reference" (RESEAT-rip-v2); the RESULTS-BOARD's own stated open problem: "No method yet gives BOTH exact geometry... AND gorgeous model-painted watercolor style... simultaneously." v2 design must treat this as the central unsolved risk, not assume the one-pass LoRA result (0.975-0.988, different collection) generalizes without re-verification.
3. **Two-gate acceptance is mandatory: geometry IoU alone produces false positives.** Marriott r3_right_s1: IoU 0.976, near-empty. Any v2 pipeline must hard-wire a vision/content judge alongside the geometry gate — never ship on one gate.
4. **Nano Banana is vetoed for narrow/tall die-cut panels — confirmed independently on two tasks.** space-np01 (aspect 1:3.4, forced 9:16, region-IoU as low as 0.0–0.6) and Marriott t2 (aspect 0.39, "aspect enum lacks tall 0.39 → recomposes all tall panels", killed from die-cut pipeline). v2 must gate model selection on aspect-enum support before spend, not discover it per-panel.
5. **Dashed template strokes leak into painted output as literal dot marks; solid-only control maps are required.** Proven and fixed at commit 4d93530 ("Marriott r12 dome tops + door-anchor dashes"), later itself found to have introduced a synthetic-anchor-inflation regression (commit a8b775f) that shipped through several rounds before being source-verified. v2 rule: any derived/synthetic geometry shape must be pixel-verified against the true template before being trusted as a gate input — a fix for one drift class can silently create another.
6. **Re-seat / exact_bevel_composite is a last-resort backstop only, never default — it measurably degrades style even while perfecting geometry.** User verdict quoted directly: "raw was good, you ruined it with exact.png." v2 must never let a deterministic geometry post-process supersede or overwrite a good raw; always keep raw + derived-exact as separate artifacts.
7. **Reference images must carry exactly ONE role each; role-mixing causes multi-round style oscillation.** Root-caused for the Marriott r15 "glossy oscillation" and fixed by the STYLE-SPEC v1 structured role map (architecture / medium / content / anti — each with its own file list). v2's reference-image contract must enforce single-role tagging, not let an agent infer multiple axes from one image.
8. **Hold-out discipline is precise, not blanket: a panel's own prior approved round is held out from its own regen, but the collection's original source art is not.** Misapplying this either way either measures memorization (using own prior round) or discards legitimate content truth (over-holding-out original source art). v2 must encode this exact scoping rule, not a vague "don't reuse refs."
9. **Substrate artifacts of a reference photo are not the target illustration style ("Rule 0").** Fiber/felt texture read from a physical product photo's material was mistakenly baked into the target style spec until user correction. v2's style-read step must explicitly separate physical-substrate artifacts of a reference photo from the illustration medium itself before building any style bible.
10. **Ad hoc round-by-round prose correction plateaus; a structured, versioned, incident-traced style-bible schema is what actually stopped the drift.** After ~15 oscillating rounds (git history r1–r16), the fix was STYLE-SPEC v1 — a 19-field matrix where every field traces to a named incident, not another manual patch. v2 workflow should adopt a persistent, versioned style-contract artifact from round 1, not defer structure until after repeated drift.
